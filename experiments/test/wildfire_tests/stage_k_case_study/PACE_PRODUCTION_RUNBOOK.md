# Stage K PACE Production Runbook

## Frozen scientific contract

- Configuration: `config/full.yaml`
- Lambda values: `0.0, 0.2, 0.5, 0.8, 1.0`
- Evaluators: GridSFM, DC-OPF, and AC-OPF
- Per evaluator and lambda: one intact state, 50 shared K=1 candidates, and at most 250 evaluator-specific K=2 candidates
- GridSFM: `q=5`, 20 alpha values, and finalist ranking by `J_total`
- Environment: Scenario 16 loading and June 23 at 16:00 CDT cumulative weather hazard
- Risk: authoritative stored baseline with squared loading
- References: AC Reference A followed by fixed-topology maximum-delivery Reference B1/B2 for each converged finalist

The scientific configuration must not be changed during recovery. Infrastructure failures may be retried from their deterministic output boundary.

## Resource contract

- GridSFM and its preflight use exactly one approved NVIDIA GPU and may not fall back to CPU. The initial preference is A100; V100 is an approved production substitute when A100 queue pressure is materially worse, provided the matching device contract and intact-case preflight pass.
- DC-OPF, AC-OPF, references, joins, and aggregation use GNR CPU nodes.
- GridSFM, DC-OPF, and AC-OPF are independent five-task arrays.
- References are a 15-task evaluator-by-lambda array, with B1 then B2 serial within each task.
- Array throttles and Slurm resource selectors are environment configuration, not scientific configuration.

## Pre-submission checks

From the repository root on Phoenix, activate the private production environment and run:

```bash
python -m pytest experiments/test/wildfire_tests/stage_k_case_study/tests -q
bash -n experiments/test/wildfire_tests/stage_k_case_study/pace/*.sh
bash -n experiments/test/wildfire_tests/stage_k_case_study/pace/*.sbatch
bash experiments/test/wildfire_tests/stage_k_case_study/pace/submit_production.sh --dry-run
```

Record the repository commit, patch SHA-256, full configuration SHA-256, input SHA-256, resource selectors, throttles, and dry-run output before submission.

## Gate P1: preparation and GPU sanity

```bash
bash experiments/test/wildfire_tests/stage_k_case_study/pace/submit_production.sh --preflight-submit
```

Wait for both jobs in `preflight_job_ids.csv`. Do not submit production arrays until:

- `prepared/input_manifest.json` reports `PASS` and matches `full.yaml`;
- `preflight/gpu/gridsfm_environment_manifest.json` reports `PASS`;
- exactly one GPU of the configured, approved type is visible;
- the pinned GridSFM package and immutable v1.1 checkpoint load on CUDA;
- intact Texas2k inference completes and produces finite outputs.

The production submitter independently enforces the two manifest checks.

## Gate P2: production submission

```bash
bash experiments/test/wildfire_tests/stage_k_case_study/pace/submit_production.sh --submit
```

For unattended queueing, this same command may be run by `stage_k_production_launch_gnr.sbatch` with an `afterok` dependency on the GPU preflight. The launcher retains the manifest hard gate, so evaluator arrays cannot be submitted from a failed or incomplete preflight.

This creates the evaluator arrays and the dependency chain for candidate joining, references, reference joining, aggregation, and final validation. Job IDs are written to `submitted_job_ids.csv`.

Monitor with `squeue`, `sacct`, the run logs, and `production_status.json`. Retry only failed infrastructure tasks, preserving evaluator, lambda, input hash, configuration hash, and candidate identity. Stop for authentication/account failures, a required scientific-method change, or a material runtime/resource deviation.

## Completion criteria

Completion requires `RUN_COMPLETE.json` from the final validator. At minimum, verify:

- 1,505 evaluated states per evaluator and 301 states per evaluator/lambda;
- exact shared K=1 identity and deterministic evaluator-specific K=2 identity;
- five finalists per evaluator and no duplicate candidate keys;
- GridSFM ranking uses `J_total = J_trade + rho * PAC_total`;
- 15 Reference A, B, and delta rows with explicit convergence statuses;
- B1 is valid for every reported finalist; B2 failures are retained as warnings, not silently discarded;
- every ineligible B2 row uses the certified B1 physical state, leaves economic tie-break cost unavailable, and preserves B2 status, iterations, and logs; any B1 failure prevents completion;
- runtime, peak memory, device, Slurm accounting, failures, and retries are preserved;
- final scientific tables and plots are generated by independent aggregation.
